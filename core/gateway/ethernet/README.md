# Роутер подключается к шлюзу кабелем через WAN

Этот режим рассчитан на модели, у которых есть порт Ethernet WAN и ручная настройка IPv4. Entware и «Клиент прокси» на таком роутере не требуются. Шлюз пересылает IPv4 TCP и UDP через группу серверов подписки. Линия поддерживает клиентов локальной сети роутера с обычным NAT. Отдельный режим для IPv6, проброс входящих портов и транзит ICMP в этой конфигурации отсутствуют. Проверяйте доступность сайта через HTTPS.

**Оборудование.** Нужен постоянно включённый Linux с локальным Docker Engine в обычном режиме rootful, Docker Compose v2 с поддержкой `up --wait`, `iproute2`, `python3`, `bash`, `flock`, поддержкой TUN, macvlan и iptables. Нужны два независимых сетевых подключения. Первое даёт шлюзу интернет. Второе — отдельный проводной Ethernet-интерфейс к WAN роутера, например USB Ethernet. Интернет самого шлюза должен продолжать работать с отсоединённым вторым кабелем. Для Windows/Docker Desktop и NAS без таких возможностей используйте режим SOCKS5, если он доступен на роутере.

1. Сохраните действующие параметры WAN в панели роутера и пометьте исходный кабель. Сначала запустите основной Compose-шлюз по инструкции в корне комплекта. Для отказоустойчивости ему нужны хотя бы два действующих сервера.
2. На Linux найдите свободный Ethernet-интерфейс командой `ip -br link`. Включите именно этот адаптер, оставьте его без IPv4, DHCP-клиента и глобальных IPv6-адресов. Значение ниже — пример имени. Замените его именем выбранного отдельного порта. Домашняя сеть роутера и другие сети шлюза должны отличаться от `192.168.247.0/30`.

   ```bash
   bash ethernet/setup.sh up enp2s0
   bash ethernet/setup.sh status
   ```

3. После успешной проверки соедините выбранный Linux-порт напрямую отдельным кабелем с Ethernet WAN роутера. На этом WAN выберите постоянный IPv4. Адрес роутера — **192.168.247.2**, маска — **255.255.255.252**, основной шлюз — **192.168.247.1**, DNS — **1.1.1.1**. DNS-запросы к этому серверу также проходят через подписку. Оставьте NAT между домашней сетью и этим WAN. Для устройств, которые должны использовать только VPN, выберите этот WAN единственным доступным выходом. Другие активные выходы в их политике могут дать прямой маршрут при отказе.
4. С устройства за роутером откройте HTTPS-сайт, посмотрите внешний IP. Для проверки отказа заблокируйте на тестовом стенде доступ к одному активному узлу подписки и повторите новый HTTPS-запрос. Внешний IP может совпадать у нескольких серверов одного провайдера. Для UDP нужен рабочий сервер подписки с поддержкой UDP. Если все серверы недоступны, новые соединения через этот WAN прекратятся.

**Возврат.** Верните прежние кабель и параметры WAN роутера. Выполните `bash ethernet/setup.sh down` из той же распакованной папки. Скрипт удалит кабельный сервис и обе его выделенные сети. При включении и выключении кабельного режима Compose может перезапустить основной SOCKS-шлюз, поэтому действующим клиентам потребуется переподключиться. Храните комплект в каталоге с доступом владельца: файлы шлюза содержат пароль и данные подписки.

**Устройство схемы.** Кабельный сервис работает в собственном сетевом пространстве Docker. Обе его сети помечены как внутренние. Основная таблица маршрутизации контейнера получает только маршруты к непосредственно подключённым сетям. Вход с адреса WAN допускается на интерфейс TUN. В отдельной таблице маршрут blackhole закрывает выход при исчезновении TUN. Прокси доступен через выделенную внутреннюю сеть Compose. Пересылка и правила iptables относятся к кабельному контейнеру. Служба DHCP здесь не запускается. Для запуска после перезагрузки нужны работающий Docker и доступный выделенный интерфейс с тем же именем.
