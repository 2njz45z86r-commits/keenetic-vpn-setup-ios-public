# VPN-шлюз для Keenetic и Netcraze

Это персональный архив. В нём находятся подписка или ссылки серверов, параметры провайдера и пароль домашнего SOCKS5. Для передачи программы другому человеку используйте общий архив установщика.

## На компьютере или NAS

1. Закрепите для постоянно включённого шлюза адрес **@LAN@** в домашней сети. Он должен принадлежать этому компьютеру или NAS. На Windows нужен работающий Docker Desktop в режиме Linux containers, на Linux или NAS — Docker с Compose v2. Включите запуск Docker после перезагрузки и проверьте, что шлюз не уходит в спящий режим.
2. Распакуйте архив в отдельную личную папку. На Linux для папки установите права 0700, для `config/config.yaml`, `config/source.json`, `config/servers.txt` (если есть) и README — 0600. При включённом SELinux добавьте к монтированию `./config:/private:ro` метку `:ro,Z` вместо `:ro`, если доступ запрещён. В Windows используйте личную папку с доступом для Docker Desktop.
3. Откройте терминал в распакованной папке. Для первого запуска требуется доступ к Docker Hub.

```sh
docker compose up -d --build
docker compose ps
docker compose exec -T gateway python -B /app/gateway.py status
```

После запуска дождитесь `healthy`. Последняя команда выводит число распознанных серверов. Если серверов меньше двух, служба не принимает домашние подключения. Сообщение о готовности подтверждает состав группы. Затем проверьте HTTPS с конкретного устройства через роутер. В брандмауэре шлюза при необходимости разрешите вход на TCP и UDP @PORT@ от адреса вашего роутера. Открывать порт из интернета не нужно.

## На роутере с компонентом «Клиент прокси»

Включите этот компонент и добавьте подключение SOCKS5. Укажите параметры из таблицы.

| Параметр | Значение |
|---|---|
| Адрес шлюза | @LAN@ |
| Порт | @PORT@ |
| Пользователь | keenetic |
| Пароль | `@PASSWORD@` |

Отметьте использование подключения для выхода в интернет. В разделе «Приоритеты подключений» создайте отдельную политику с этим подключением и назначьте ей нужное устройство. Самому компьютеру или NAS со шлюзом оставьте обычный выход в интернет, иначе получится петля. Проверяйте DNS и доступность нужных приложений с назначенного устройства. Перед удалением шлюза верните устройство в его прежнюю политику. [Инструкция Netcraze по клиенту прокси](https://support.netcraze.ru/air/nc-1613/ru/49443-proxy-client.html)

## Роутер с Ethernet WAN без клиента прокси

На отдельном Linux-шлюзе с дополнительным Ethernet-портом доступен кабельный вариант. Роутеру нужен WAN с ручной настройкой IPv4. Сначала запустите и проверьте основной шлюз, затем следуйте [инструкции по изолированному кабельному подключению](ethernet/README.md). Этот режим меняет подключение к интернету для устройств, использующих данный WAN.

## Подписка и автоматический выбор

Шлюз запускает Mihomo v1.19.34 и его группу URLTest. Для новых соединений выбирается доступный узел с учётом задержки. Проверка HTTPS выполняется с интервалом 60 секунд и допуском 50 мс. Длительность восстановления зависит от ответа узлов. Существующему соединению может понадобиться переподключение. Если подходящих узлов нет, трафик группы не переключается на прямой выход.

Подписка по URL проверяется раз в час. При временной недоступности источника сохраняется последний подтверждённый список для этой подписки. Вручную вставленный список остаётся фиксированным. Шлюз читает поддерживаемые Mihomo ссылки VLESS, VMess, Trojan, Shadowsocks, ShadowsocksR, Hysteria, Hysteria2, TUIC, AnyTLS и Mieru (mierus), в обычном тексте или Base64. Абонентские ограничения и параметры доступа задаёт провайдер. Для закрытой ссылки Happ Crypt требуется обычная ссылка подписки, выданная провайдером. Если источник возвращает YAML, JSON, HTML или иной формат вместо списка ссылок, используйте у провайдера экспорт share links. [Документация URLTest](https://wiki.metacubex.one/en/config/proxy-groups/url-test/) · [Конвертер ссылок в этой версии](https://github.com/MetaCubeX/mihomo/blob/v1.19.34/common/convert/converter.go)

В Compose опубликованы только TCP и UDP @PORT@ на @LAN@. SOCKS5 использует аутентификацию. Для UDP нужна действующая TCP-ассоциация того же клиента. Внутренний интерфейс управления доступен только внутри контейнера. В образ попадают программа и скрипт запуска. Личные файлы подключаются при запуске из папки config.

Остановить шлюз и сохранить кэш можно из этой папки.

```sh
docker compose down
```
